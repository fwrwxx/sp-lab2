# PRD: Motion-Mirroring Teleoperator (Дзеркалення руху руки на сервоприводах)

**Версія:** 1.0
**Дата:** 04.10.2026
**Автор:** Штифлюк Ольга Володимирівна
**Курс:** Системне програмування вбудованих систем
**Лабораторна:** ЛР №1 - Налаштування середовища розробки та bring-up STM32-платформи
**Форма виконання:** B (симулятор Wokwi)

---

## A. Загальна ідея

Пристрій являє собою систему дистанційного керування, у якій оператор одягає на кисть руки модуль IMU (MPU-6050), а віддалений маніпулятор на сервоприводах точно повторює рухи його руки в реальному часі. Система знаходить застосування в:

- **Медичній робото-хірургії** (Intuitive Surgical da Vinci) - хірург керує маніпулятором через рукавичку з IMU;
- **Ліквідації аварій** (роботи на АЕС, у хімічних середовищах) - оператор залишається в безпеці, а робот виконує точні рухи;
- **VFX-моушн-кепчер** - запис рухів актора для подальшої анімації;
- **Роботизована реабілітація** - екзоскелети, що допомагають пацієнтам відновлювати моторику.

У контексті навчальної лабораторної роботи цей проєкт демонструє повний цикл роботи з сенсорами в реальному часі: зчитування даних з IMU через I²C, обчислення орієнтації (sensor fusion), формування PWM-сигналу для сервоприводів, збереження траєкторії у flash-пам'яті, відображення стану системи на LCD-дисплеї. Головна метрика якості - **end-to-end латентність менше 50 мс** між рухом руки та реакцією сервопривода.

## B. Функціональні вимоги

| ID | Вимога | Пріоритет | Метрика |
|----|--------|-----------|---------|
| **FR-01** | Система повинна зчитувати дані з IMU MPU-6050 (акселерометр + гіроскоп) через I²C з частотою не менше 100 Гц | Високий | Частота опитування ≥ 100 Гц |
| **FR-02** | Система повинна обчислювати кути орієнтації (pitch, roll, yaw) за допомогою комплементарного фільтра | Високий | Похибка ≤ 5° |
| **FR-03** | Система повинна перетворювати кути орієнтації у PWM-сигнали для двох сервоприводів (pan + tilt) | Високий | Частота PWM = 50 Гц, діапазон 500–2500 мкс |
| **FR-04** | Система повинна забезпечувати end-to-end латентність ≤ 50 мс між рухом IMU та реакцією серво | Високий | Latency ≤ 50 мс |
| **FR-05** | Система повинна фільтрувати тремтіння руки (dead-zone ±2° та low-pass фільтр) | Середній | Стабільність серво без «смикання» |
| **FR-06** | Система повинна відображати поточний режим (IDLE / LIVE / RECORD / PLAYBACK) на LCD1602 через I²C | Середній | Оновлення LCD ≥ 5 Гц |
| **FR-07** | Система повинна записувати траєкторію руху у SPI-flash W25Q64 з delta-encoding + keyframes | Середній | Запис ≥ 1000 семплів |
| **FR-08** | Система повинна відтворювати записану траєкторію без оператора (режим playback) | Середній | Відтворення 1:1 за часом |
| **FR-09** | Система повинна перемикати режими через кнопку B1 (PC13) з антибрязкітним захистом (debounce) | Низький | Перемикання за ≤ 50 мс |
| **FR-10** | Система повинна виводити діагностику через UART (fps, latency, кути) кожні 500 мс | Низький | UART 115200 8N1 |

## C. Список датчиків та модулів

| Компонент | Модель | Інтерфейс | Призначення у проєкті | Альтернативи |
|-----------|--------|-----------|------------------------|--------------|
| **IMU** | MPU-6050 (GY-521) | I²C @ 0x68, 400 kHz | Зчитування прискорення та кутової швидкості (FR-01, FR-02) - основа для всієї системи | GY-89 (додає магнітометр і барометр - надлишково); LSM6DS3 (дорожче, ніж потрібно) |
| **Сервоприводи** | SG92R × 2 | PWM (TIM3 CH1, TIM3 CH2) | Фізичне дзеркалення руху - pan (обертання) та tilt (нахил) (FR-03) | MG90S (металеві шестерні - дорожче); SG90 (слабший момент) |
| **Flash-пам'ять** | W25Q64 | SPI @ ~5 MHz | Збереження траєкторії руху для playback (FR-07, FR-08) | W25Q128 (більше пам'яті - надлишково); AT25SF041 (менше) |
| **Дисплей** | LCD1602 + I²C-модуль PCF8574 | I²C @ 0x27, 100 kHz | Відображення режиму та статусу (FR-06) | SSD1306 OLED (дорожче, але яскравіше) |
| **Кнопка** | B1 (вбудована у Nucleo) | GPIO (PC13) | Перемикання режимів IDLE / LIVE / RECORD / PLAYBACK (FR-09) | Зовнішня тактова кнопка (потрібне додаткове підключення) |
| **UART** | ST-Link VCP (вбудований) | USART2 @ 115200 | Діагностика та налагодження (FR-10) | FT232RL (потрібен, якщо ST-Link зайнятий) |

### Обґрунтування вибору MPU-6050

MPU-6050 - це класичний вибір для задач motion-tracking:
- **6-DOF** (3-axis accelerometer + 3-axis gyroscope) - достатньо для обчислення pitch/roll без магнітометра;
- **Вбудований DMP** (Digital Motion Processor) - можна використати для апаратного sensor fusion (ускладнено, але є);
- **I²C @ 400 kHz** - швидке зчитування (14 байт за ~0.3 мс);
- **Широко документований** - багато прикладів, бібліотек, туторіалів;
- **Дешевий** - ~$2 за GY-521 breakout.

Альтернатива GY-89 (10-DOF) надлишкова, бо магнітометр у приміщенні страждає від магнітних перешкод, а барометр не потрібен для двовісної орієнтації.

### Обґрунтування вибору SG92R

SG92R - мікросервопривід з металевими шестернями:
- **Момент 2.5 кг·см** - достатньо для легкої платформи з MPU;
- **Живлення 4.8–6 В** - можна від 5 В USB;
- **PWM 50 Гц** - стандартний протокол, легко генерується HAL;
- **Висока точність** - ±1° повторюваність.

## D. План тестування

| FR | Метод тестування | Критерій успіху |
|----|------------------|-----------------|
| **FR-01** | Запустити I²C-scan, перевірити адресу 0x68; виміряти частоту зчитування через логічний аналізатор | Адреса знайдена, ≥ 100 Гц |
| **FR-02** | Порівняти обчислені кути з еталонними (нахилити плату на відомі кути 0°, 30°, 45°, 90°) | Похибка ≤ 5° |
| **FR-03** | Виміряти PWM на осцилографі/логічному аналізаторі Wokwi | Частота 50 Гц, імпульс 500–2500 мкс |
| **FR-04** | GPIO-toggle на моменті «IMU-дані отримано» та «PWM оновлено»; виміряти різницю | ≤ 50 мс |
| **FR-05** | Порівняти рух серво з увімкненим та вимкненим фільтром; оцінити візуально | Без «смикання», плавний рух |
| **FR-06** | Перемикати режими кнопкою; перевірити, що LCD оновлюється | LCD показує IDLE/LIVE/REC/PLAY |
| **FR-07** | Записати 1000 семплів; перевірити через UART кількість | 1000 семплів у flash |
| **FR-08** | Записати траєкторію, відключити IMU, запустити playback | Відтворення руху без IMU |
| **FR-09** | Натиснути кнопку 100 разів; перевірити, що не було подвійних спрацювань | debounce працює |
| **FR-10** | Перевірити UART-вивід у Serial Monitor Wokwi | Рядки з fps/latency/кутами |

### Тестовий сценарій для Wokwi

Оскільки Wokwi - симулятор, реалістичний сценарій виглядає так:
1. У `diagram.json` MPU-6050 під'єднаний до I²C1 (PB8/PB9).
2. У симуляторі Wokwi можна **змінювати орієнтацію MPU-6050 мишкою** (клік на компоненті → слайдери X/Y/Z).
3. Прошивка зчитує нові значення, обчислює кути, оновлює PWM.
4. Сервоприводи на схемі фізично повертаються відповідно до зміни орієнтації.
5. LCD1602 показує режим та поточні кути.
6. Serial Monitor виводить fps та latency кожні 500 мс.

## E. Поза межами обсягу (Out of Scope)

- Реальна передача даних по радіо (Wi-Fi, Bluetooth) - тільки UART-емуляція через ST-Link;
- Магнітометр (yaw) - тільки pitch/roll (бо MPU-6050 без магнітометра не дає абсолютного yaw);
- Реальні сервоприводи - тільки симуляція Wokwi;
- Камера OV7670 - не підтримується Wokwi;
- FreeRTOS - використовується bare-metal з HAL (для простоти).

## F. Ризики та пом'якшення

| Ризик | Ймовірність | Пом'якшення |
|-------|-------------|-------------|
| Wokwi не підтримує MPU-6050 DMP | Висока | Використовуємо програмний complementary filter |
| I²C конфлікт між MPU (0x68) та LCD (0x27) | Низька | Різні адреси - конфлікту немає |
| Latency > 50 мс через повільний I²C | Середня | I²C @ 400 kHz (Fast Mode) замість 100 kHz |
| Тремтіння серво | Висока | Dead-zone + low-pass фільтр (FR-05) |
| Flash не встигає за потоком даних | Низька | Delta-encoding + буферизація (FR-07) |
