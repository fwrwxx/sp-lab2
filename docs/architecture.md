# Архітектура проєкту

Проєкт реалізовано за принципом **шаруватої архітектури** (Layered Architecture). Головне правило - напрямок залежностей: `App` → `Devices` → `Platform` → `Core (HAL)`.

## Шари:
1. **`Core/`**: Згенерований STM32CubeMX код (ініціалізація HAL, переривання, `main.c`). Не редагується вручну.
2. **`Platform/`**: Адаптація до конкретної плати. Містить інтерфейс `bus.h` (абстракція шин I2C/SPI) та його реалізацію `board.c` (HAL SPI та програмний bit-bang I2C).
3. **`Devices/`**: Драйвери сенсорів (`mpu6050.c`). Залежать **лише** від `bus.h`. Не знають про існування HAL.
4. **`App/`**: Бізнес-логіка продукту (`app.c`). Викликає функції драйверів. Не знає про HAL.
5. **`tests/`**: Хостові тести (компілюються звичайним `gcc`), які використовують `fake_bus.c` для імітації шин.

## Автоматична перевірка правил залежностей:
Скрипт `scripts/check_deps.sh` перевіряє, що жоден файл з `App/` або `Devices/` не включає `stm32c0xx_hal.h`. Це гарантує, що бізнес-логіка залишається незалежною від заліза.
